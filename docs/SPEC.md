# Blockyees — техническое задание

Версия 1.0 · 16 сентября 2026 года

Платформа: iPadOS. Репозиторий: https://github.com/prankster-d/blockyees. Основная ветка: `main`.

Статус: спецификация для реализации. Приложение ещё не разработано. Подтверждённый функциональный объём и предлагаемые технические решения разделены ниже.

## 1. Назначение

Blockyees — графический блокнот для iPad с синхронизацией и планируемой публикацией в App Store. Пользователь создаёт файлы с редактируемыми страницами, рисует и размещает изображения, организует файлы по папкам и выбирает порядок просмотра страниц.

Ключевое требование — полноценный редактор. Нельзя сокращать согласованный набор инструментов ради быстрой реализации. Холст с единственной кистью не является завершённым результатом.

В приложении нет таймингов страниц, отдельных комментариев к страницам, воспроизведения страниц, аудио и видеоэкспорта. Надписи и рисунки непосредственно на холсте остаются частью содержимого.

## 3. Редактор и работа со страницами

Реестр определяет обязательные функциональные группы. Точные параметры, жесты и состояния необходимо детализировать перед реализацией и проверить на iPad. Нельзя считать функцию готовой только по наличию кнопки.

| ID | Функциональная группа | Что проверить |
|---|---|---|
| E01 | Рисование и стирание, выбор цвета и размера инструмента. | Штрихи, настройки, переключение инструментов, точность ввода. |
| E02 | Настройки ввода пальцем и Apple Pencil, фиксированный размер штриха, прямые линии. | Каждый режим ввода; отсутствие случайного стирания или рисования при навигации. |
| E03 | Undo/redo. | Обратимость поддерживаемых действий; согласованность содержимого после отмены и повтора. |
| E04 | Выделение, перенос, масштабирование и поворот содержимого. | Выделяется ожидаемая область; преобразование не повреждает остальную страницу. |
| E05 | Слои: создание, порядок, копирование, вставка, видимость, прозрачность. | Изменения затрагивают нужный слой и сохраняются после открытия файла. |
| E06 | Импорт изображений в страницу и слой, drag-and-drop. | Правильное место вставки и сохранение изображения. |
| E07 | Onion skin с выбором соседних страниц и слоя. | Правильное отображение соседей без изменения содержимого текущей страницы. |
| E08 | Создание, вставка, дублирование, копирование и удаление страниц. | Корректный состав файла; дубликат редактируется независимо. |
| E09 | Размеры страниц, масштаб и зеркалирование холста. | Геометрия рисунка и управление холстом. |
| E10 | Режимы обзора страниц и масштаб миниатюр. | Удобное открытие страниц при разных размерах представления. |
| E11 | Жесты, команды внешней клавиатуры и темы оформления. | Согласованный набор команд и сохранение настроек. |
| E12 | Открытие, сохранение, импорт и экспорт файлов. | Состав содержимого и редактируемость в поддерживаемых форматах. |

Для каждой группы подготовить текстовый контракт: действия, параметры, состояния, ожидаемый результат, отмена и сохранение. Перечень конкретных кистей, жестов, сочетаний клавиш и форматов пока не зафиксирован; это задача детализации, а не основание исключать функции.

## 4. Сортировка страниц

Согласованные режимы:

- **По умолчанию** — основная последовательность страниц файла.
- **Более поздние страницы вверху** — дополнительный порядок просмотра.

Подтверждённое правило: в режиме «Более поздние страницы вверху» редактирование старой страницы поднимает её наверх. Порядок определяется последним изменением содержимого страницы, а при отсутствии правок — её созданием.

1. Основная последовательность хранится независимо от выбранного режима.
2. Второй режим сортирует по времени последнего изменения по убыванию. Совпадения разрешаются детерминированным дополнительным ключом.
3. Новая страница появляется первой. Правка существующей страницы поднимает её на первое место.
4. Просмотр страницы, переключение сортировки и перемещение файла не считаются правкой содержимого и не меняют этот порядок.
5. Переключение режима не меняет содержимое и идентификаторы страниц.
6. Возврат к основному порядку восстанавливает основную последовательность.
7. В горизонтальном обзоре начало списка эквивалентно верху вертикального обзора.
8. Пустой файл и файл с одной страницей обрабатываются без ошибок.

Проектное решение A02: запоминать выбранный режим отдельно для каждого файла и сохранять текущую открытую страницу при переключении. Во время штриха страница не должна перескакивать: момент обновления обзора определить в контракте редактора.

Пример: созданы A, B, C — порядок C, B, A. После правки A — A, C, B. После создания D — D, A, C, B.

Для импортированных страниц без достоверного времени изменения нужно определить явное правило. Также определить влияние сортировки на переходы в редакторе, onion skin и экспорт. Синхронизация должна сохранять порядок при одинаковом наборе данных на устройствах.

## 5. Папки и файлы

Файл-блокнот содержит страницы. Папка содержит файлы-блокноты. В корне библиотеки доступны папки и файлы без папки.

Сценарий создания папки: вызвать создание → ввести название → подтвердить → открыть новую папку. Пустая папка корректно отображается и сохраняется после перезапуска.

Сценарий перемещения: выбрать файл → вызвать перемещение → выбрать назначение → подтвердить → открыть файл в новом месте. Файл исчезает из прежнего расположения, его содержимое и настройки сохраняются.

Предлагаемые инженерные правила A03:

- Отмена операции ничего не меняет.
- Перемещение в текущую папку не создаёт копию.
- Пустое название папки не принимается.
- Совпадение названий не приводит к перезаписи существующих файлов.
- Ошибка перемещения оставляет исходный файл доступным.
- Идентичность файла определяется стабильным ID, а не названием или путём.

Вложенные папки, массовые операции, переименование и удаление папок не входят в подтверждённые добавления. Их необходимость и поведение определяются отдельно; не расширять объём автоматически.

## 6. Сохранение и техническая модель

Предлагаемая модель A04:

| Сущность | Основные данные |
|---|---|
| Folder | ID, название. |
| Notebook | ID, название, необязательный folderID, основная последовательность страниц, режим сортировки. |
| Page | ID, даты создания и последней правки, сведения для согласования изменений, свойства страницы, редактируемое содержимое. |
| Drawing | Слои, изображения и данные редактирования в формате выбранного движка. |

Это логическая схема, не утверждённый формат хранения. Окончательный формат выбрать после проверки движка и требований к переносу файлов.

Требования к надёжности:

- Сохранённые данные доступны после закрытия и повторного открытия приложения.
- Сортировка меняет представление, а не содержимое и основную последовательность.
- Перемещение не преобразует рисунки и не удаляет единственную копию при ошибке.
- Слои не превращаются в единую плоскую картинку при обычном сохранении.
- Изменение формата хранения допускает восстановление исходных данных.

Кандидат реализации — нативное приложение iPadOS. Конкретные технологии выбрать после проверки функциональности редактора. Само наличие поддержки Pencil у компонента недостаточно: требуется покрытие всего согласованного реестра. Веб-макет не является поставкой приложения для iPad.

Цель — максимально широкая поддержка iPad и стилусов. Буквальная совместимость со всеми выпущенными моделями не подтверждена: минимальную iPadOS и матрицу устройств предстоит выбрать по возможностям редактора. Базовый ввод не должен зависеть от давления или специальных жестов стилуса; дополнительные возможности включаются только при поддержке оборудованием. Матрица тестовых устройств, объём тестовых файлов и пределы производительности будут определены при технической проверке. Численные бюджеты размера документа, числа страниц и задержки ввода определить по измерениям на целевом устройстве до окончательного выбора движка.

## 7. Импорт, синхронизация и выпуск

Импорт существующих блокнотов обязателен. Он должен сохранять страницы, слои, изображения и редактируемое содержимое. Неподдерживаемое содержимое нельзя молча отбрасывать или заменять плоской картинкой. Формат входных файлов необходимо исследовать на небольшом тестовом документе. Исходный файл остаётся неизменным при успешном и неуспешном импорте.

Синхронизация обязательна; конкретный сервис ещё не согласован. iCloud — кандидат, а не уже утверждённая реализация. Требуется определить обработку параллельных правок, удалений, перемещений, отсутствия сети и повторных попыток. Минимальный критерий: при конфликте не теряется ни одна версия рисунка, а после восстановления связи данные сходятся на устройствах. Работа без сети с последующей отправкой изменений — предлагаемое поведение A05.

Цель выпуска — App Store. Нужны установка тестовой сборки на iPad, проверка редактора, совместимости, импорта и синхронизации, затем подготовка карточки приложения, сведений о данных и политики конфиденциальности. Финальная отправка и выпуск — отдельный этап после проверки сборки.

Открытые решения:

| ID | Вопрос | Следующее действие |
|---|---|---|
| Q02 | Как сортировка влияет на переходы, onion skin и экспорт? | Зафиксировать единый контракт. |
| Q03 | Как сортировать импортированные страницы без даты правки? | Выбрать явное правило. |
| Q05 | Точный формат импортируемых файлов и обязательные форматы экспорта. | Исследовать тестовый документ; видеоэкспорт исключён. |
| Q06 | Минимальная iPadOS, матрица устройств и модель тестового iPad. | Подготовить предложение по широкой совместимости и проверить его. |
| Q07 | Сборка и установка. | Подготовить воспроизводимую сборку и проверить установку на поддерживаемые устройства. |
| Q08 | Сервис синхронизации и правила конфликтов. | Предложить архитектуру, проверить обмен между двумя устройствами. |
| Q09 | Модель распространения. | Бесплатное или платное распространение будет определено до выпуска. |

Техническое исследование выполняет исполнитель. Вопросы об инструментах реализации не перекладываются на пользователя.

## 8. Последовательность реализации

1. Детализировать реестр редактора и закрыть влияющие на архитектуру вопросы. Результат — проверяемые контракты функций.
2. Проверить движок на iPad: рисование, слои, преобразования, undo/redo, сохранение. Если обязательная функция не поддерживается, пересмотреть движок, а не сокращать набор инструментов.
3. Реализовать библиотеку, документы и страницы. Подтвердить сохранение и повторное открытие.
4. Реализовать два режима сортировки, папки, перемещение, импорт и синхронизацию. Проверить отсутствие повреждения данных и обработку конфликтов.
5. Выполнить приёмочные сценарии на устройствах, подготовить устанавливаемую сборку и комплект для App Store.

Весь код, документация, тесты и материалы проекта ведутся в данном репозитории. Изменения в Git публикуются после подходящей проверки, с подтверждением удалённого SHA; готовность кода и готовность приложения на устройстве учитываются отдельно.

## 10. Готовность

Приложение готово, когда сборка установлена на целевом iPad, обязательные сценарии пройдены, весь согласованный реестр редактора проверен, существенные открытые решения закрыты, а сохранение данных подтверждено.

Успешная компиляция, макет или работа только в симуляторе недостаточны для окончательной приёмки.
